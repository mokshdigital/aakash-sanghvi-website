01 — Context

The Problem

A growing field services company with multiple offices, dozens of technicians, and hundreds of active work orders — held together by spreadsheets and tribal knowledge.

📋

Fragmented Tools

Work orders in one system, scheduling in another, timesheets on paper, invoicing in spreadsheets. No connection between them.

🔀

Scheduling Conflicts

Dispatchers had no visibility into tech availability or workload. Double-bookings were common.

⏳

Delayed Invoicing

Weeks between job completion and invoice prep. Missing information meant constant back-and-forth.

👥

Multiple User Types

Admins, dispatchers, office staff, field techs, and clients — each with different needs, no unified system.

My Approach

Embedded, Not Remote

I didn't build from a spec document. I went on-site, sat with dispatchers, watched techs in the field, and talked to management. Every feature came from a real conversation, not a ticket. As both the product owner and developer, I could make a decision at 10am and ship it by 3pm.

Traditional Approach

  • Requirements doc → weeks of dev → demo → feedback
  • Decisions made in meetings
  • Feedback filtered through PMs
  • Sprint cycles (2–4 weeks)

My Approach

  • Conversation → build → ship → feedback → iterate
  • Decisions made face-to-face with users
  • Direct observation of workflows
  • Daily shipping cycles

The Tech Dashboard

A separate mobile-first product built for non-technical field workers. Designed from on-site observation — watching technicians try to use the system with gloves on, in direct sunlight, between tasks.

📱

Mobile-First UX

Large tap targets, minimal text input, quick-select buttons for common values. No training manual needed.

✅

Task Execution

See assigned tasks, mark complete/blocked with attribution, upload site photos and safety docs per task.

⏱️

Field Time Logging

Log hours per job per date. Quick-select buttons (0.5, 1, 2, 4, 8h). Status-aware — greyed out when day is submitted.

🔧

Materials Tracking

Log materials used on-site with receipt photo upload. Source tracking (purchased vs shop inventory). Reimbursement requests.

When dispatch updates a work order, reassigns a tech, or adds a task — the field tech sees it instantly without refreshing. Supabase realtime subscriptions across tasks, assignments, comments, and day notes keep everyone in sync.

04 — AI Integration

AI-Powered Tools

Two AI features that save hours of manual work — with human-in-the-loop safety so the AI assists but never acts alone.

Natural Language Report Generator

Users ask a question in plain English — "Show me all active jobs in Vancouver with more than 20 logged hours" — and get a fully composed dashboard with charts, tables, and KPI cards. No SQL knowledge needed.

[ Screenshot: AI Report Generator — prompt input + generated dashboard with charts ]
  • How it works: Gemini AI reads a pruned database schema, generates SQL + UI layout JSON, user confirms before execution
  • 5 widget types: Metric cards, bar charts, line charts, pie charts, data tables — composed dynamically
  • Safety layers: System prompt guardrails → regex validation → Postgres function validation → read-only execution
  • Voice input: Ask questions by speaking — Web Speech API transcription

AI Work Order Creator

Paste an email, upload a PDF, or record audio — the AI extracts structured work order data and walks you through a step-by-step wizard. One click creates the full work order with tasks, checklists, tech assignments, and an auto-generated PDF.

[ Screenshot: AI WO Creator — multimodal input + step wizard ]
  • Multimodal input: Text paste, file upload (PDF/images), audio recording — all analyzed together
  • Smart matching: Fuzzy matches extracted client/PM/tech names against existing database records
  • Full injection: Creates WO + tasks + checklists + tags + assignments + PDF in one transaction

Hard Problems Solved

Status-Based UI Locking

A ternary permission chain that controls what's editable at each WO status. Different statuses unlock/lock different parts of the UI for different roles.

Multi-Office Filtering

A single global selector that filters every module (WOs, calendar, billing, timesheets, people) — without being a permission boundary.

Realtime Collaboration

Supabase realtime subscriptions across tasks, assignments, comments, and day notes. Office updates appear on field tech phones instantly.

Designing for the Field

Building for users who aren't technical — field techs on phones in the sun, office staff who live in spreadsheets, clients who just want their files.
